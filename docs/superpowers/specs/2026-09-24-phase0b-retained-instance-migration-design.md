# Phase 0B retained-instance migration handoff

Status: two-path concept approved by the owner on 2026-09-24; independent written review passed for the start/projection identity chain and destination replay requirements; awaiting owner review of this complete amendment before implementation. This amends only the service-handoff part of the [Phase 0B launch identity bridge](2026-09-24-phase0b-launch-identity-bridge.md). It does not authorize a model request or freeze Paper 1 parameters.

## Context and objective

The old AutoDL instance is powered off but retained, with its instance and data disk expected to be restartable. Its Phase 0A-1 judge v2 run was previously verified as 797/797 coded, with zero unresolved dispatches. That historical result must be verified again from retained durable evidence before migration. Powering off may have terminated the old vLLM process without allowing the judge service's normal `stop` command to write stop evidence. Neither a missing stop record nor a retained disk proves the service is still running.

The migration must preserve the old judge archive as historical evidence, start an independent Phase 0B service on the new server, and retain an honest account of which old-service termination path was observed. No Phase 0B request may be attributed to the old judge service identity.

## Two exclusive old-service paths

Before choosing a path, restart the retained instance only when migration work is ready, inspect it read-only, and verify the judge's final projection, manifest, journal replay, 797 coded items, and zero unresolved dispatches. Verify the original service-start record's schema and contents, and bind its instance, service identity, manifest and environment lock to the judge projection; isolated hashes are insufficient. Record the old instance identity, archive root, relevant file hashes, old service start-identity hash, observed process/PID/session/port state, and observation time. Do not read raw response text into logs or chat. If the archive is missing, corrupt, or replay-ambiguous, fail closed; no claim of verified judge completion or migration handoff is permitted.

1. **Live-service path.** Use this only if the exact recorded judge service process is still active and the original script's PID, process start time, executable, command line, session, and loopback listener checks all pass. Stop that process using the original judge service lifecycle command and its own recorded identity. Verify the resulting stop evidence, port absence, and empty GPU compute-process observation. Keep the existing normal-stop bridge semantics.
2. **Cold-poweroff path.** Use this only if the original process is absent after restart and the port and GPU compute-process checks show no old service. Record the retained instance's current boot/host observation, old start-identity hash, old terminal judge projection hash, absence checks and observation time in a distinct, content-addressed `cold-poweroff` handoff record. The cold verifier must re-open the original start record and judge projection, check their schemas and the same instance/service/manifest/lock identity chain, and reject a pair of unrelated hashes. Its wording must state only that the service was absent at the post-restart observation and that the termination time and manner are unverified; do not infer a precise shutdown event or graceful stop. It must not be called, encoded as, or accepted in place of `judge-service-stop-evidence.v1`. Any conflicting or uncertain process/port/GPU observation blocks both paths until investigated.

The two paths are a discriminated union: exactly one verified termination kind is bound to the new Phase 0B service bridge. A normal-stop receipt is never synthesized from a cold-poweroff observation. The existing normal-stop verifier remains strict; the cold branch is a separate schema and verifier, not an optional or nullable stop-hash shortcut.

## Data and new-host boundary

- Copy the required judge evidence and model artifacts to an external archive on the new host or retained storage; use a completeness-checked source-to-destination inventory and SHA-256 exact-match checks. Re-open the destination's essential judge start/manifest/lock/projection/journal evidence and replay its terminal verification, including 797 coded items and zero unresolved dispatches; matching the files listed in an incomplete inventory is not enough. Preserve the original archive unchanged. Large raw evidence remains outside Git and is never printed in chat.
- Do not infer that a copied model directory has the same revision merely from its name. Verify pinned model/tokenizer artifacts and the new host's actual environment before service startup.
- The new host gets a fresh preliminary environment inspection, its own pre-service `Phase0BLaunchIntent`, absent preflight/full-run archive roots, and a fresh `start-first` service identity. New paths and configuration hashes are derived from the new host, not copied from the old service identity. The launch intent remains independent of the later adapter binding and final authorization.
- Bind the verified old judge projection and its validated original start/manifest/lock chain, one verified old-service termination kind, the source/destination archive inventory and replay result, launch intent, fresh inspection and new service-start identity into a content-addressed migration bridge. The bridge must reject unrelated old judge/service records, old/new service identity equality, mismatched or incomplete copies, altered source or destination identity, and an inspection or service command that differs from the new host's actual evidence.
- Do not resume, merge, or re-label the old judge run. Do not reuse its vLLM start identity for Phase 0B. The Phase 0B two-event preflight and 480-event archive remain disjoint and create-only.

## Approval and failure gates

Read-only inspection of the retained instance does not authorize any model requests. Before starting the new service, obtain the existing exact source-bundle and launch-intent approvals. After the new service identity exists, derive the exact adapter binding, diagnostic authorization and twelve manifests, verify them, and obtain the existing final hash approval before *any* Phase 0B model request, including the two-event preflight.

If the retained archive cannot be verified, if the old process state is ambiguous, if migration hashes differ, or if the new inspection fails, stop at that boundary and ask the owner how to proceed. Never repair the evidence by re-running judge requests or silently downgrading the 797-item completion claim. All outputs remain `preliminary`, `not_frozen`, and `formal_parameter_authority=false`.

## Local acceptance tests

Focused tests must accept a correctly linked normal-stop path and a correctly linked cold-poweroff path. They must reject forged normal-stop receipts, mixed or missing termination kinds, mismatched old start/projection/manifest/lock identity or replay hashes, nonempty GPU or occupied port observations, incomplete or changed archive copies, new-service identity reuse, launch-intent/inspection drift, and an attempted Phase 0B dispatch before final authorization approval. Cloud Linux checks must use actual retained-instance and new-instance evidence; local synthetic fixtures prove only the contract logic.
