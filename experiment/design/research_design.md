## 一、研究问题 (Research Questions)

### RQ1: 演化速率与拓扑轨迹
当封闭的社会意见网络高度依赖具有强"生成式把关"特征的大语言模型进行信息交互时，其宏观社会认知图谱（方差与网络模块度）走向"观点均质化"的演化速率与拓扑坍缩特征是什么？

### RQ2: 对齐效应的差异验证
RLHF 安全对齐机制（相较于安全向量切除的对照组）在多大程度上加速了系统方差的收敛，强化了"观点均质化"进程？安全对齐所导致的角色漂移（Persona Drift）是否构成收敛加速的中介机制？

> *注：人类代理节点（Human Proxies）作为另一类多样性干预，留待后续研究（Paper 2）探讨。*

## 二、核心实验设计

### 2.1 网络构建

| 参数 | 设定 |
|------|------|
| 节点数 (N) | **200 agents**（正式实验）；20 agents（Phase 0 试点） |
| 拓扑结构 | 无标度网络 (Barabási-Albert)，参数 m 由 Phase 0 敏感性分析确定（候选 m=2 或 m=3） |
| 交互模式 | 每轮随机激活 **40** 个节点发言（约20%激活比例） |
| 交互轮数 | 50轮（视试点收敛曲线可调整） |
| Temperature | 0.7（暂定，待文献查阅后固定；写入 experiment.yaml 作为受控变量） |
| 记忆窗口 | k=3（每邻居保留最近3轮发言） |
| 邻居采样 | 每轮按度数平方根加权（α=0.5）采样最多10个邻居；α值由 Phase 0 敏感性分析确定（候选 α=0 / α=0.5） |

### 2.2 Agent设计

#### LLM Agent
- **角色设定**: 系统提示词定义初始立场（如"25岁激进左翼青年"、"40岁保守派企业主"）
- **初始观点**: 1-10分正态分布
- **记忆机制**: 本地List存储历史对话，滑窗保留最近k轮

### 2.3 交互循环流程

```
每轮循环（同步更新机制）:
1. 感知与截断
   - 所有激活节点统一读取上一轮结束时邻居的状态快照
   - 从直接邻居中按度数平方根加权（α=0.5）随机采样，最多取10个
   - 每个采样邻居保留最近 k=3 轮发言，构建 Prompt
   - 估算 token：10 × 3 × 65 ≈ 1,950 tokens，加系统提示共约 2,500-3,000 tokens
   - 注：本轮任何节点的新观点在本轮内对其他节点不可见

2. 思考与更新（并发执行）
   - 所有激活节点并发调用 API 生成新观点文本 + 自报评分（50字+【评分：X】）

3. 广播（统一写入）
   - 本轮所有新观点统一写入，广播给直接邻居（图结构中的连接节点，非全部200个）
   - 进入下一轮
```

## 三、实验分组（核心自变量）

### 网络A：控制组（加速均质化环境）
- **构成**: 100% Qwen2.5-7B-Instruct（强对齐）
- **机制**: 测试RLHF对齐模型是否导致观点中庸化收敛
- **系统提示词**: 标准对齐提示词

### 网络B：对照组（安全对齐向量切除）
- **构成**: 100% Qwen2.5-7B-Instruct-abliterated（安全向量切除版）
- **机制**: 与网络A架构完全相同（SFT+RLHF权重结构保留），仅安全对齐方向向量被置零；两组唯一差异即"安全对齐"的有无
- **系统提示词**: 与网络A相同（两组提示词完全一致）
- **模型来源**: HuggingFace 社区版；若无合适版本，使用 FailSpy/abliterator 自行生成

### 网络C：实验组（竞争性共生的负熵干预）
- **构成**: 90% Instruct模型 + 10% Human Proxy节点
- **机制**: 测试真实人类噪音能否抵抗AI同质化

> *注：本文（Paper 1）仅研究网络A与网络B的对比。网络C留待 Paper 2 实施。*

## 四、技术方案决策

### 4.1 部署方式：AutoDL 云端（已确定）

| 对比维度 | API调用 | 本地 CPU | **AutoDL 云端（选定）** |
|---------|---------|---------|----------------------|
| 变量控制 | 差（无法获取 abliterated 模型） | 差（无独立 GPU） | **优（fp16全精度，权重固定）** |
| 模型精度 | 不可控 | 需 INT4 量化 | **fp16 全精度** |
| 成本 | $50-500 | 免费但极慢 | **~¥40（全部实验）** |
| 可复现性 | 厂商可能更新模型 | 可复现 | **完全可复现** |
| 推荐显卡 | — | — | **RTX 4090 / 4090D（24GB）** |

### 4.2 模型选择

**最终选择**: Qwen2.5系列

| 组别 | 模型 | 来源 |
|------|------|------|
| 对齐版（网络A） | Qwen2.5-7B-Instruct | ModelScope: `Qwen/Qwen2.5-7B-Instruct` |
| 安全向量切除版（网络B） | Qwen2.5-7B-Instruct-abliterated | HuggingFace 社区版（优先）；或用 FailSpy/abliterator 自行生成 |

**选择理由**:
1. 两组架构完全相同（SFT + RLHF 权重结构），唯一差异为安全对齐方向向量的有无
2. 两组均使用相同 chat 格式，消除交互格式混淆变量
3. 自变量精确对应"RLHF 安全对齐"，可在结论中明确归因
4. Abliteration 技术已有 Song et al. (2025) 的理论支撑（见附录）

**运行策略**:
两组实验**分时运行**（先跑完网络A全部重复 → 再跑网络B），每次只加载一个模型，使用全部 24GB，保持 fp16 全精度，无需量化。

### 4.3 服务框架：vLLM（推荐）

| 框架 | 难度 | 性能 | 适用场景 |
|-----|------|------|---------|
| Ollama | ⭐ 简单 | 一般 | 快速验证 |
| **vLLM** | ⭐⭐ 中等 | **高** | **正式实验** |
| TGI | ⭐⭐⭐ 复杂 | 高 | 备选 |

**vLLM优势**:
- Continuous Batching自动优化吞吐
- 兼容OpenAI API格式（代码改动小）
- 支持并发控制（防止OOM）

## 五、并发执行方案

### 5.1 核心机制

模型无状态，Agent历史由实验层管理：

```
模型服务层               实验管理层
Qwen2.5-7B-Instruct  ←──  Agent 1:   历史记录 [list]
（或 abliterated）    ←──  Agent 2:   历史记录 [list]
无状态，每次请求独立   ←──  Agent 3:   历史记录 [list]
                      ←──  ...
                      ←──  Agent 200: 历史记录 [list]
```

### 5.2 推荐实现：异步并发

```python
# 控制并发数防止OOM
semaphore = asyncio.Semaphore(10)  # RTX 4090建议10

async def bounded_task(agent_id, task):
    async with semaphore:
        result = await task
        return agent_id, result
```

### 5.3 性能估算

**Phase 0 试点（20 agents × 50轮）**

## 六、测量指标（因变量）

### 6.1 主指标：观点评分时序（数值化）

每轮记录全体 agent 的自报评分（1-10），计算：
- **方差时序**：每轮观点分布方差（↓ = 多样性消失）
- **均值时序**：每轮均值是否向5漂移（↓偏离两极 = 中庸化）
- **收敛半衰期**：方差下降至初始值50%所需轮数

**提取方式**：Prompt 末尾强制要求输出 `【评分：X】`，正则解析，解析失败则记录异常并排除。

# 验证指标考虑，困惑度和信息熵！！！

### 6.2 验证指标：语义嵌入相似度

- **模型**：`BAAI/bge-large-zh-v1.5`
- **指标**：每轮所有 agent 文本输出的平均两两余弦相似度（↑ = 语义趋同）
- **用途**：与评分方差趋势交叉印证；若两套指标方向一致，结论更可信

**可信度检验**：Spearman 相关系数（自报评分 vs 嵌入向量位置），ρ > 0.6 视为有效。

### 6.3 宏观网络拓扑

- **模块度 (Modularity)**：网络模块度→0 表示失去多重观点派别
- **社群数量**：动态检测观点社群演变（基于评分分段聚类）

### 6.4 机制验证指标：角色一致性得分（Persona Consistency Score）

角色漂移是 RLHF 把关效应的中介机制，而非噪声，需正面测量与报告：

```
角色一致性得分(t) = cosine( embed(第t轮输出), embed(初始角色描述) )
```

- **预期**：网络A（Instruct）角色一致性随轮次单调下降；网络B（abliterated）保持相对稳定
- **作用**：作为论文机制验证图，解释"Instruct 网络收敛更快"的内在路径——安全对齐持续侵蚀 agent 维持极端立场的意愿
- **嵌入模型**：复用 `BAAI/bge-large-zh-v1.5`，与验证指标共用，无额外计算成本

### 6.5 文本多样性（补充）
- **Self-BLEU**：全体节点生成文本的词汇多样性分数

## 八、关键问题与解决方案

### 问题1: 自变量孤立——如何精确测量"安全对齐"效应
**挑战**: 若对比 Instruct vs Base 模型，差异包含 SFT+RLHF 全部影响，且两者交互格式不同，产生混淆变量。
**解决**: 采用 **abliterated 模型**（安全向量切除版）作为对照——保留相同 SFT+RLHF 权重结构，仅切除安全对齐方向向量。两组使用完全相同的 chat 格式与 Prompt，唯一差异精确对应"安全对齐向量"的有无。

### 问题2: 人类代理语料异质性
> *此问题已延至 Paper 2，暂不考虑。*

### 问题3: 并发控制与显存管理
**风险**: 200个节点的并发请求可能OOM
**解决**:
- 两组实验分时运行，每次只加载一个模型，独占全部 24GB VRAM，fp16 全精度，无需量化
- 使用 Semaphore 限制并发数（RTX 4090 建议从 10 开始，逐步测试至 15-20）
- vLLM 启动参数：`--max-num-seqs 20 --gpu-memory-utilization 0.90`

### Agent Prompt 模板（结构化输出）

```python
SYSTEM_PROMPT = """你是一个{role_description}。
你对"{topic}"这一议题有自己的立场和看法。"""

USER_PROMPT = """你的邻居们最近表达了以下观点：
{neighbor_statements}

请表达你对上述议题的当前看法（50字以内），
并在最后一行单独输出你的立场评分，格式严格为：
【评分：X】
（X为1到10的整数，1=极端反对该议题，10=极端支持该议题）"""

# 评分提取
import re
def extract_score(text: str) -> int | None:
    match = re.search(r'【评分：(\d+)】', text)
    if match:
        score = int(match.group(1))
        return score if 1 <= score <= 10 else None
    return None
```

## 十四、研究局限性（待论文写作时展开）

### L1：同步更新 vs 异步更新
本研究采用**同步更新机制**（所有激活节点读取上一轮快照后统一更新），与 DeGroot、HK 等经典意见动力学模型对标，保证可复现性与变量控制。
然而，现实社交媒体（微博、朋友圈等）更接近**异步更新**：用户发帖后立即可见，后来者的观点已受先发帖者影响。异步机制下 hub 节点的同轮内放大效应更强，均质化可能加速。未来研究可探索异步更新机制对均质化动力学的影响，以检验本研究结论的稳健性。

### L2：未设置随机基线（Null Model）
本研究未设置随机回复节点作为零模型对照。理由：已有文献（Nature, [citation]）正式证明 LLM 意见网络中观点坍缩为长期动力学的必然结果，"收敛是否发生"已是已知结论；本研究聚焦于 RLHF 安全对齐对坍缩**速率与程度**的调节效应，零模型基线对此核心论证无额外价值。未来研究可通过引入随机基线进一步验证网络拓扑对收敛速率的独立贡献。
