## Phase -1：8 项关键设计决策（2026-03-24）

### 决策 1：节点规模调整（100 → 200）

| 项目 | 内容 |
|------|------|
| **变更前** | 100 agents |
| **变更后** | 200 agents（正式实验） |
| **核心收益** | 生态效度提升（真实社会网络规模下限） |
| **影响** | 正式实验时长从~10 分钟增至~20 分钟（RTX 4090，并发 20） |

**决策依据**：导师建议，200 为真实社会网络规模下限，保证结论外部效度。

---

### 决策 2：对照组模型选择（Base → abliterated）

| 项目 | 内容 |
|------|------|
| **变更前** | Qwen2.5-7B-Base |
| **变更后** | Qwen2.5-7B-Instruct-abliterated（安全向量切除版） |
| **核心收益** | 精确孤立安全对齐效应（消除 SFT+chat 格式混淆） |

**决策依据**：
```
Instruct vs Base 的差异 = SFT 差异 + RLHF 差异 + chat 格式差异（× 混淆变量过多）
Instruct vs abliterated 的差异 = 仅 RLHF 安全对齐差异（√ 精确归因）
```

**实操**：优先使用 HuggingFace 社区版；若无合适版本，使用 FailSpy/abliterator 自行生成（约 2-3 小时）

---

### 决策 3：部署方式调整（本地/API → AutoDL 云端）

| 项目 | 内容 |
|------|------|
| **变更前** | 本地 CPU 或 API 调用 |
| **变更后** | AutoDL 云端 RTX 4090/4090D |
| **核心收益** | fp16 全精度，成本可控（~¥40），模型版本固定 |

**决策依据**：
- 本地无独立 GPU，无独立显存
- API 调用无法获取 abliterated 模型，且模型版本不可控
- AutoDL 按秒计费， RTX 4090 约¥2-3/小时，全部实验预计~¥40

---

### 决策 4：更新机制调整（异步 → 同步）

| 项目 | 内容 |
|------|------|
| **变更前** | 异步更新（先更新的节点立即可见） |
| **变更后** | 同步更新（所有节点读取上一轮快照后统一更新） |
| **核心收益** | 与经典模型对标，消除激活顺序隐变量 |

**决策依据**：
- 异步更新下，激活顺序成为隐变量，影响可复现性
- 同步更新与 DeGroot (1974)、Hegselmann-Krause (2002) 等经典意见动力学模型对标
- 牺牲部分生态效度（真实社交媒体更接近异步更新），换取变量控制与可复现性

**记入论文局限性**：异步更新（对应微博/朋友圈实时信息流场景）会产生更快的收敛速度，且激活顺序本身成为影响变量；本研究采用同步机制以保证可复现性和变量控制，未来研究可探索异步机制下的收敛动力学差异。

---

### 决策 5：邻居采样设计（全连接 → 度数加权有限注意力）

| 项目 | 内容 |
|------|------|
| **变更前** | 全连接网络（读取所有邻居发言） |
| **变更后** | 度数平方根加权采样（α=0.5），最多读取 10 个邻居，每邻居保留最近 3 轮 |
| **核心收益** | Token 可控（~2,500），模拟算法推荐机制 |

**决策依据**：
- 全连接网络下 hub 节点 token 溢出（200 节点→单节点 199 邻居×3 轮×65 字≈38,000 tokens）
- 有限注意力（bounded attention）符合认知科学原理
- 度数加权模拟算法推荐机制（热门内容更易被看到）

**Phase 0 敏感性分析**：同时测试 α=0（均匀随机）与 α=0.5（度数加权）

---

### 决策 6：统计方法升级（t 检验 → LMM 线性混合模型）

| 项目 | 内容 |
|------|------|
| **变更前** | t 检验（仅比较第 50 轮终点均值） |
| **变更后** | LMM 线性混合模型（`方差 ~ 轮次 × 组别 + (1+轮次\|run_id)`） |
| **核心收益** | 充分利用 250 个数据点（50 轮×5 次重复），统计功效大幅提升 |

**决策依据**：
- t 检验仅能比较终点差异，丢失 50 轮时序信息
- 无法回答"收敛速率是否有差异"这一核心问题
- LMM 可检验轮次×组别交互项（两组收敛斜率差异），配置信带直接作为论文主图

---

### 决策 7：角色漂移定位为中介机制

| 项目 | 内容 |
|------|------|
| **变更前** | 未明确角色漂移的定位 |
| **变更后** | 角色漂移 = RLHF 把关效应的中介机制 |
| **核心收益** | 机制链条完整（RLHF → 角色漂移 → 收敛加速） |

**决策依据**：
- 初期仅关注方差收敛，未解释"为什么 Instruct 收敛更快"
- 角色漂移不是噪声，而是 RLHF 把关效应的具体实现路径
- 新增**角色一致性得分**指标：`cosine(embed(第 t 轮输出), embed(初始角色描述))`

**论文机制链条**：
```
RLHF 安全训练 → 模型被训练成"拒绝维持极端立场"
    → 多轮对话中主动软化角色（角色漂移）
    → 观点向中庸收敛
    → 这正是"生成式把关"的机制本身
```

### 决策 8：Phase 0 试点设计

| 项目 | 内容 |
|------|------|
| **变更前** | 无试点，直接进入 200 节点正式实验 |
| **变更后** | Phase 0：20 节点×50 轮，同时完成 m 值和α值敏感性分析 |
| **核心收益** | 降低正式实验失败风险，参数选择有据可依 |

**敏感性分析矩阵**（8 次运行）：

| 组合 | m 值 | α值 | 模型组别 |
|------|-----|-----|---------|
| 1 | 2 | 0 | Instruct |
| 2 | 2 | 0.5 | Instruct |
| 3 | 3 | 0 | Instruct |
| 4 | 3 | 0.5 | Instruct |
| 5 | 2 | 0 | abliterated |
| 6 | 2 | 0.5 | abliterated |
| 7 | 3 | 0 | abliterated |
| 8 | 3 | 0.5 | abliterated |

**决策规则**：
- 若各参数趋势一致（仅速度差异）→ 选收敛最清晰的组合用于正式实验
- 若某参数产生定性差异 → 正式实验需将该参数作为调节变量分析
