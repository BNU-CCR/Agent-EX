#### 2.2.2 实验设计核心参数

**网络构建参数**：
| 参数 | 设定值 | 说明 |
|------|--------|------|
| 节点数 (N) | 200 agents | 正式实验；20 agents（Phase 0 试点） |
| 拓扑结构 | 无标度网络 (Barabási-Albert) | m 值待 Phase 0 敏感性分析确定（候选 m=2 或 m=3） |
| 交互模式 | 每轮随机激活 40 个节点发言 | 约 20% 激活比例 |
| 交互轮数 | 50 轮 | 视 Phase 0 收敛曲线可调整 |
| Temperature | 0.7 | 待文献查阅后固定，或 Phase 0 补测 0.3/0.7/1.0 |
| 记忆窗口 | k=3 | 每邻居保留最近 3 轮发言 |
| 邻居采样 | 度数平方根加权（α=0.5），上限 10 | α值待 Phase 0 敏感性分析确定（候选 α=0/0.5） |

**Agent 设计**：
- **角色设定**：系统提示词定义初始立场（如"25 岁激进左翼青年"、"40 岁保守派企业主"）
- **初始观点**：1-10 分正态分布
- **记忆机制**：本地 List 存储历史对话，滑窗保留最近 k 轮
- **输出格式**：50 字观点文本 +【评分：X】（正则提取）

**同步更新机制**：
```
每轮循环（同步更新）:
1. 感知与截断：所有激活节点统一读取上一轮结束时邻居的状态快照
2. 邻居采样：从直接邻居中按度数平方根加权（α=0.5）随机采样，最多取 10 个
3. 记忆构建：每个采样邻居保留最近 k=3 轮发言，估算 token≈2,500-3,000
4. 思考与更新：所有激活节点并发调用 API 生成新观点
5. 广播：本轮所有新观点统一写入，广播给直接邻居
```

#### 2.2.3 关键设计决策与问题解决

过去三周通过导师讨论与文献查阅，解决了以下核心设计问题：

**决策 1：节点规模调整（100 → 200）**
- **问题**：初始设计 100 节点被质疑生态效度不足
- **解决**：导师建议，200 为真实社会网络规模下限，保证结论外部效度
- **影响**：正式实验时长从~10 分钟增至~20 分钟（RTX 4090，并发 20）

**决策 2：对照组模型选择（Base → abliterated）**

| 对比维度 | 最初设计（有问题） | 修正后设计 |
|---------|------------------|-----------|
| 实验组 | Qwen2.5-7B-Instruct | Qwen2.5-7B-Instruct |
| 对照组 | Qwen2.5-7B-Base | Qwen2.5-7B-Instruct-abliterated |

- **问题**：Instruct vs Base 的差异 = SFT 差异 + RLHF 差异 + chat 格式差异。若发现两组有差异，无法说清是 SFT、RLHF 还是 chat 格式导致的
- **解决**：采用 abliterated 模型（安全向量切除版）—— 与 Instruct 使用完全相同的 chat template，架构完全相同（SFT+RLHF 权重结构保留），唯一差异为安全对齐方向向量被置零
- **影响**：两组差异可精确归因于"RLHF 安全对齐"效应，消除混淆变量

**决策 3：部署方式调整（本地/API → AutoDL 云端）**
- **问题**：本地无独立 GPU，API 调用无法获取 abliterated 模型且模型版本不可控
- **解决**：AutoDL 租用 RTX 4090，fp16 全精度，分时运行两组实验（先网络 A 全部重复，再网络 B）
- **成本**：~¥40（全部实验，含环境配置与调试）

**决策 4：更新机制调整（异步 → 同步）**

| 更新机制 | 异步更新（最初设计） | 同步更新（修正后） |
|---------|-------------------|------------------|
| 运作方式 | 节点激活后立即可见 | 所有节点读取上一轮快照后统一更新 |
| 问题 | 激活顺序成为隐变量，同轮内信息不对称 | 无激活顺序效应 |
| 可复现性 | 差（每次激活顺序不同） | 强（相同初始条件→相同结果） |
| 对标模型 | — | DeGroot (1974)、Hegselmann-Krause (2002) |

- **问题**：异步更新下，先激活的节点会影响后激活的节点，激活顺序成为隐变量，影响可复现性
- **解决**：改为同步更新，与经典意见动力学模型对标
- **影响**：牺牲部分生态效度（真实社交媒体更接近异步更新），换取变量控制与可复现性

**决策 5：邻居采样设计（全连接 → 度数加权有限注意力）**
- **问题**：全连接网络下 hub 节点 token 溢出（200 节点全连接 → 单节点 199 邻居 × 3 轮 × 65 字 ≈ 38,000 tokens）
- **解决**：每轮按度数平方根加权（α=0.5）采样最多 10 个邻居，每邻居保留最近 k=3 轮发言
- **影响**：单节点 token 控制在~2,500-3,000，符合 vLLM 推理优化区间；同时模拟算法推荐机制（热门内容更易被看到）

**决策 6：统计方法升级（t 检验 → LMM）**

| 对比维度 | t 检验（最初设计） | LMM 线性混合模型（修正后） |
|---------|------------------|-------------------------|
| 数据利用 | 仅用终点数据（第 50 轮） | 充分利用 50 轮×5 次=250 个数据点 |
| 检验内容 | 两组终点均值差异 | 轮次×组别交互（收敛速率差异） |
| 统计功效 | 低 | 高 |
| 模型公式 | — | `方差 ~ 轮次 × 组别 + (1+轮次\|run_id)` |

- **问题**：t 检验仅能比较终点差异，丢失 50 轮时序信息，无法回答"收敛速率是否有差异"
- **解决**：采用 LMM，固定效应检验轮次×组别交互，随机效应控制 5 次重复的非独立性
- **影响**：充分利用 250 个数据点，可检验收敛速率差异，统计功效大幅提升
- **示例解读**：若轮次×组别交互显著（β = -0.023, p = 0.004）→ Instruct 组每轮方差下降速度比 abliterated 组快 0.023 → RLHF 安全对齐显著加速了观点均质化进程

**决策 7：角色漂移定位为中介机制**
- **问题**：初期仅关注方差收敛，未解释"为什么 Instruct 收敛更快"
- **解决**：将角色漂移定位为 RLHF 把关效应的中介机制，新增角色一致性得分作为机制验证指标
- **影响**：论文机制链条完整：RLHF → 角色漂移 → 收敛加速

**决策 8：Phase 0 试点设计**
- **问题**：直接进入 200 节点正式实验风险高，参数未经检验
- **解决**：增设 Phase 0（20 节点×50 轮），同时完成 m 值和α值敏感性分析
- **影响**：降低正式实验失败风险，确保参数选择有据可依

#### 2.2.5 测量指标体系

**主指标：观点评分时序**
- **方差时序**：每轮观点分布方差（↓ = 多样性消失）
- **均值时序**：每轮均值是否向 5 漂移（↓ = 中庸化）
- **收敛半衰期**：方差下降至初始值 50% 所需轮数

**验证指标：语义嵌入相似度**
- **模型**：BAAI/bge-large-zh-v1.5
- **指标**：每轮所有 agent 文本的平均两两余弦相似度（↑ = 语义趋同）
- **用途**：与评分方差趋势交叉印证

**可信度检验**：Spearman 相关系数（自报评分 vs 嵌入向量位置），ρ > 0.6 视为有效

**宏观网络拓扑**
- **模块度 (Modularity)**：网络模块度→0 表示失去多重观点派别
- **社群数量**：动态检测观点社群演变（基于评分分段聚类）

**机制验证指标：角色一致性得分**
```
角色一致性得分 (t) = cosine( embed(第 t 轮输出), embed(初始角色描述) )
```
- **预期**：网络 A（Instruct）角色一致性随轮次单调下降；网络 B（abliterated）保持相对稳定
- **作用**：作为论文机制验证图，解释"Instruct 网络收敛更快"的内在路径

**文本多样性（补充）**
- **Self-BLEU**：全体节点生成文本的词汇多样性分数

### 2.2.6 敏感性分析矩阵详解

**问题**：实验设计中有两个参数需要通过 Phase 0 试点确定。

**待确定的两个参数**：

| 参数 | 含义 | 候选值 | 影响 |
|------|------|--------|------|
| **m** | BA 网络每新增一个节点连接的边数 | 2 或 3 | m 越大→网络越密集→观点传播越快 |
| **α** | 邻居采样的度数加权指数 | 0 或 0.5 | α越大→hub 节点影响力越强 |

**敏感性分析矩阵（8 次运行）**：

| 运行编号 | m 值 | α值 | 模型组别 | 目的 |
|---------|-----|-----|---------|------|
| 1 | 2 | 0 | Instruct | 测试 m=2, 均匀采样时 Instruct 的收敛曲线 |
| 2 | 2 | 0.5 | Instruct | 测试 m=2, 度数加权时 Instruct 的收敛曲线 |
| 3 | 3 | 0 | Instruct | 测试 m=3, 均匀采样时 Instruct 的收敛曲线 |
| 4 | 3 | 0.5 | Instruct | 测试 m=3, 度数加权时 Instruct 的收敛曲线 |
| 5 | 2 | 0 | abliterated | 测试 m=2, 均匀采样时 abliterated 的收敛曲线 |
| 6 | 2 | 0.5 | abliterated | 测试 m=2, 度数加权时 abliterated 的收敛曲线 |
| 7 | 3 | 0 | abliterated | 测试 m=3, 均匀采样时 abliterated 的收敛曲线 |
| 8 | 3 | 0.5 | abliterated | 测试 m=3, 度数加权时 abliterated 的收敛曲线 |

**设计逻辑**：2 参数 × 2 水平 × 2 组别 = 8 次

**参数含义详解**：

```
m 值（BA 网络参数）：
├── m = 2：每新增一个节点连接 2 条边 → 网络较稀疏
├── m = 3：每新增一个节点连接 3 条边 → 网络较密集
└── 影响：m 越大 → 网络连通性越好 → 观点传播越快 → 均质化可能加速

α值（邻居采样加权指数）：
├── α = 0：均匀采样，所有邻居被选中的概率相同 → 模拟"随机浏览"
├── α = 0.5：度数平方根加权，hub 节点被选中的概率更高 → 模拟"算法推荐"
└── 影响：α 越大 → hub 节点影响力越强 → 可能加速均质化
```

**决策规则**：

```
情况 1：各参数组合趋势一致（仅收敛速度差异）
→ 选择收敛最清晰的组合用于正式实验
→ 在论文中说明参数选择依据

情况 2：某参数产生定性差异（如 m=2 收敛，m=3 不收敛）
→ 正式实验需将该参数作为调节变量分析
→ 可能产生有趣的理论发现（如"网络密度调节均质化效应"）
```

**每次运行输出指标**：
- 方差时序曲线（50 轮内每轮的方差）→ 主图，观察收敛趋势
- 收敛半衰期（方差降至初始 50% 所需轮数）→ 比较不同参数的收敛速度
- 最终方差（第 50 轮）→ 判断是否完全均质化
- 角色一致性时序（50 轮内角色一致性得分）→ 机制验证

**BA 网络 m 值疑问**（需文献确认）：
- 背景疑问：m=3 是否意味着每个节点只有 3 个邻居？那还需要随机采样吗？
- BA 网络生长机制：新节点依次加入，每个新节点连接 m 条边到已有节点（优先连接度数高的节点）
- 最终结果：早期节点可能成为 hub（50+ 邻居），晚期节点至少 m 个邻居
- 因此仍需邻居采样：hub 节点邻居过多，无法全部读取
