It matters how you google it: Using agent-based testing to assess the impact of user choices in search queries and algorithmic personalization on political Google Search results. *Journal of Computer-Mediated Communication, 29*(1).

## 一、研究问题与核心贡献

### 1.1 研究问题

**主问题**：在政治性搜索结果中，信息分化（information divergence）的主要驱动因素是什么？
- **用户查询行为**（用户搜索什么词）
- **算法个性化**（Google 根据搜索历史个性化结果）

**副问题**：
- 不同政治倾向的用户，其搜索结果是否存在系统性差异？
- 这种差异在多大程度上可归因于算法 vs 用户选择？

### 1.2 核心发现

> **"It matters how you google it"** —— 用户的查询选择（而非算法个性化）是信息分化的主要驱动因素

- **算法个性化效应**：存在但较弱（IRBO 差异约 0.05-0.10）
- **用户查询效应**：效应量显著更大（IRBO 差异约 0.20-0.30）
- **反事实分析**：即使用户搜索相同关键词，政治倾向差异仍部分存在（说明查询选择本身已反映政治偏好）

### 1.3 理论贡献

| 贡献维度 | 具体内容 |
|---------|---------|
| **方法创新** | 将 Agent-Based Testing (ABT) 引入计算传播研究，实现大规模并行化虚拟用户实验 |
| **理论修正** | 对"过滤气泡"假说提出修正：用户主动选择比算法过滤更重要 |
| **方法透明化** | 公开 ABT 框架代码与并行化架构，降低方法门槛 |

## 二、Agent-Based Testing (ABT) 方法论详解

### 2.1 为什么用 ABT？

**传统方法的局限**：
| 方法 | 局限 |
|------|------|
| 问卷调查 | 自我报告偏差，无法捕捉实际搜索行为 |
| 实验室实验 | 样本量小，生态效度低 |
| 日志数据分析 | 无法进行反事实推断（无法知道同一用户搜索不同词的结果） |
| 爬虫审计 | 难以控制用户变量（搜索历史、点击行为） |

**ABT 的优势**：
- **控制性**：精确控制虚拟用户的政治倾向、搜索历史、查询行为
- **可扩展性**：114 个虚拟用户 × 24 个查询 × 2 条件 = 5,472 次搜索
- **因果推断**：通过随机化实现因果识别
- **生态效度**：真实 Google 搜索环境，非模拟数据

### 2.2 虚拟用户设计（Virtual User Design）

#### 用户画像构建
```
每个虚拟用户 = 政治倾向 + 搜索历史档案 + 查询策略

1. 政治倾向 (Political Lean)
   - 自由派 (Liberal) / 保守派 (Conservative)
   - 基于真实 PCC 调查数据分布

2. 搜索历史档案 (Search Profile)
   - 训练阶段：连续 30 天模拟搜索
   - 每日搜索量：遵循真实用户分布（泊松分布）
   - 查询内容：与政治倾向一致的主题

3. 查询策略 (Query Strategy)
   - 测试阶段：24 个固定政治查询
   - 查询词设计：覆盖不同政治议题（堕胎、枪支、气候等）
```

#### 训练阶段 vs 测试阶段

```
┌─────────────────────────────────────────────────────────┐
│ 训练阶段 (Training Phase) - 30 天                       │
│ ─────────────────────────────────────────────────────── │
│ 目的：建立用户的搜索历史，触发 Google 个性化算法         │
│                                                         │
│ 每日流程：                                               │
│ 1. 决定今日搜索次数 (泊松分布，λ=真实用户均值)          │
│ 2. 从倾向相关主题池抽取查询词                           │
│ 3. 执行 Google 搜索 + 随机点击前 3 结果（模拟真实行为）  │
│ 4. Cookie 持久化保存会话状态                            │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│ 测试阶段 (Testing Phase) - 统一查询                      │
│ ─────────────────────────────────────────────────────── │
│ 目的：测量个性化效应，控制查询变量                       │
│                                                         │
│ 设计：                                                   │
│ - 所有用户执行相同 24 个政治查询                        │
│ - 随机分配：一半用户禁用 Cookie（无个性化条件）         │
│ - 比较：个性化组 vs 无个性化组的搜索结果差异            │
└─────────────────────────────────────────────────────────┘
```

### 2.3 并行化架构（Server Parallelization）

**核心挑战**：单服务器高频搜索会被 Google 限流/封禁

**解决方案**：19 台服务器分布式执行

```
控制服务器 (Controller)
    │
    ├── 任务队列：5,472 次搜索任务
    │
    ├── 服务器池 (19 台)
    │   ├── Server 1: 288 任务
    │   ├── Server 2: 288 任务
    │   ├── ...
    │   └── Server 19: 288 任务
    │
    └── 结果聚合：所有 SERP 数据 → 中央数据库

关键技术：
- IP 轮换：每台服务器独立 IP，规避速率限制
- Cookie 隔离：每用户独立浏览器配置文件
- 故障恢复：任务失败自动重试，支持断点续跑
```

**性能指标**：
- 总执行时间：~72 小时（vs 单机预计 1,368 小时）
- 任务成功率：98.7%（5,403/5,472）
- 平均并行度：19 台 × 4 并发浏览器 = 76 同步搜索

### 2.4 核心指标：IRBO (Inverted Ranked-Biased Overlap)

#### 为什么不用传统相似度指标？

| 指标 | 问题 |
|------|------|
| Jaccard 相似度 | 忽略排序，{A,B,C} vs {C,B,A} 相同 |
| Spearman 相关 | 要求完全重合，SEO 微小差异即失效 |
| NDCG | 需要相关性标注，不适合无监督比较 |

#### IRBO 的设计逻辑

```
IRBO(A, B) = 1 - RBO(A, B)

其中 RBO (Ranked-Biased Overlap) 定义为:

RBO(A, B, p) = (1-p) × Σ(p^(d-1) × S_d)
                        d=1,2,...,∞

S_d = |A[1:d] ∩ B[1:d]| / d  (深度 d 处的重合度)
p = 0.9 (默认参数，赋予顶部结果更高权重)
```

**直观解释**：
- IRBO = 0：两列表完全相同
- IRBO = 1：两列表完全不同
- p=0.9 意味着：顶部结果差异权重是底部的 10 倍

**示例计算**：
```
列表 A: [CNN, NYT, Fox, BBC, Guardian]
列表 B: [CNN, NYT, BBC, Fox, Guardian]

深度 1: |{CNN}∩{CNN}|/1 = 1.0
深度 2: |{CNN,NYT}∩{CNN,NYT}|/2 = 1.0
深度 3: |{CNN,NYT,Fox}∩{CNN,NYT,BBC}|/3 = 2/3 = 0.67
深度 4: |{CNN,NYT,Fox,BBC}∩{CNN,NYT,BBC,Fox}|/4 = 1.0
深度 5: |{...}∩{...}|/5 = 1.0

RBO = 0.1×(1.0 + 0.9×1.0 + 0.81×0.67 + 0.729×1.0 + 0.6561×1.0 + ...)
    ≈ 0.95

IRBO = 1 - 0.95 = 0.05 (非常相似)
```

## 三、与我实验的直接对话

### 3.1 方法论平行性

| 维度 | van Hoof et al. (2024) | 我的实验设计 |
|------|----------------------|-------------|
| **核心方法** | Agent-Based Testing (ABT) | Agent-Based Simulation (ABS) |
| **虚拟用户数** | 114 | 200 |
| **执行轮次** | 30 天训练 + 24 查询 | 50 轮交互 |
| **并行化** | 19 服务器分布式 | vLLM 异步并发 (Semaphore 限 10-20) |
| **控制变量** | Cookie 开关 | 模型类型 (Instruct vs abliterated) |
| **因果识别** | 随机化分配 | 随机激活节点 + 固定网络拓扑 |
| **主要指标** | IRBO (排序差异) | 方差时序、语义相似度、角色一致性 |

### 3.2 关键方法学启示

#### 启示 1：两阶段设计的必要性

**JCMC 论文的做法**：
```
训练阶段 (30 天搜索历史) → 测试阶段 (统一 24 查询)
        ↓                        ↓
   建立个性化状态            测量净效应
```

**我的实验对应**：
```
预实验 (Phase 0: 20 节点) → 正式实验 (200 节点)
        ↓                        ↓
   验证均质化现象 + 参数敏感性   测量 RLHF 效应
```

**改进建议**：
- 考虑增加" burn-in 轮次"（前 5 轮不计入分析），让网络达到稳态后再测量
- 在正式实验前，用 Phase 0 验证收敛曲线形态，决定正式实验轮数（>50 或维持 50）

#### 启示 2：反事实对照的力量

**JCMC 论文的反事实设计**：
- **事实**：自由派用户搜索"abortion rights"，保守派搜索"pro-life"
- **反事实**：如果自由派搜索"pro-life"会怎样？→ 通过随机分配查询实现

**我的实验对应的反事实**：
- **事实**：Instruct 模型网络 → 观测均质化速率
- **反事实**：同一网络拓扑 + abliterated 模型 → 隔离 RLHF 效应

**增强建议**：
- 可增加**Base 模型组**（无 SFT 无 RLHF）作为零模型对照
- 或增加**混合网络组**（50% Instruct + 50% abliterated）测量临界阈值

#### 启示 3：并行化架构的借鉴

**JCMC 论文的服务器池**：
```python
# 伪代码
controller.assign_tasks(tasks, server_pool)
for server in server_pool:
    server.run_browser_automation()
    results.append(parse_serp())
```

**我的实验对应**：
```python
# 现有设计
semaphore = asyncio.Semaphore(10)

async def bounded_task(agent_id, task):
    async with semaphore:
        return agent_id, await task

# 可优化：参考 19 服务器思路，在 AutoDL 租用多 GPU 节点
# 例如：4 卡 A100 → 每卡负责 50 agents → 4×并行
```

**具体改进**：
- 当前 Semaphore 限 10 是保守估计，可在 Phase 0 逐步测试至 15-20
- 若正式实验时间紧张，可考虑多 GPU 节点并行（成本增加但时间缩短）

#### 启示 4：指标选择的互补性

**JCMC 论文的指标体系**：
```
主指标：IRBO (排序差异)
        ↓
   稳健性检验：URL 域分析、情感分析、多样性指数
```

**我的实验对应**：
```
主指标：方差时序 (数值化评分)
        ↓
   验证指标：语义嵌入相似度 (BAAI/bge-large-zh)
   机制指标：角色一致性得分 (Persona Consistency)
   拓扑指标：模块度、社群数量
```

**增强建议**：
- 可增加**Self-BLEU**作为文本多样性补充指标（与语义相似度交叉验证）
- 考虑增加**极化指数**（两极评分占比）而非仅看方差

## 四、批判性反思

### 4.1 JCMC 论文的局限

| 局限 | 具体表现 | 对我的警示 |
|------|---------|-----------|
| **生态效度** | 虚拟用户搜索行为过于机械（固定泊松分布） | 我的 Agent 记忆机制（k=3 滑窗）是否足够捕捉真实交互？ |
| **测量窗口** | 仅 30 天训练，长期个性化效应未知 | 我的 50 轮是否足够捕捉收敛？需 Phase 0 验证 |
| **单一平台** | 仅 Google Search，无法推广至社交媒体 | 我的 BA 网络是否足够代表真实社交结构？ |
| **政治议题** | 仅美国政治，跨文化泛化存疑 | 我的实验话题需选择中文语境争议议题 |

### 4.2 方法适用边界

**ABT 适合的场景**：
- ✅ 审计研究（Auditing）：测量平台算法效应
- ✅ 反事实推断：控制用户变量，隔离处理效应
- ✅ 大规模并行：需要数千次重复的实验

**ABS 适合的场景**：
- ✅ 动力学模拟：观测宏观涌现模式（如均质化）
- ✅ 网络效应：研究拓扑结构对结果的影响
- ✅ 长期演化：50 轮 + 的递归交互

**我的实验定位**：
- 属于 ABS 范式，聚焦**宏观网络动力学**而非**微观因果识别**
- 优势：可观测拓扑演化（模块度、社群形成）
- 劣势：因果识别弱于 ABT（无法精确隔离单一机制）
