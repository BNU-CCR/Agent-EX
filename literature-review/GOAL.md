# Agent-EX 文献梳理：持续推进目标

## 北极星目标

在 **2022 年 1 月 1 日至每次实际检索截止日** 的范围内，建立一套以 **LLM-based Social Simulation / Generative Agent-Based Modeling 方法论** 为核心的可核查文献与学术发表知识库，系统理解该方法的研究范式、智能体架构、环境与互动协议、校准验证、外部效度、报告规范和可复现性；持续追踪其主要学科、期刊与会议发表生态；据此明确当前 Agent-EX 论文的投稿路径，并识别可发展为独立方法论文的后续贡献。

## 研究优先级

1. **方法范式**：LLM-based social simulation、generative ABM、synthetic societies、LLM as social simulators。
2. **方法构件**：agent architecture、persona、memory、environment、interaction protocol、time/update scheduling、information flow、measurement。
3. **校准与验证**：calibration、benchmark、human/empirical validation、external/ecological validity、sensitivity、ablation、model bias。
4. **实验报告与可复现性**：ODD、TRACE、CoMSES、prompt/model/version disclosure、randomness、seed、cost、failure/retry、replication。
5. **理论到模型的转化**：社会科学理论如何落实为主体属性、行为规则、互动关系与宏观结果。
6. **学科应用与直接对照**：新闻传播、政治、社会心理、经济、组织、健康、教育、生态等应用；Agent-EX 的意见动力学、网络与社会影响研究保留为应用/对照层。

新闻传播学是用户的学科基础与重要应用场景，但不再预设为方法论文唯一或首要发表共同体。跨学科方法研究为最高优先级。

## 必须形成的长期成果

- **方法知识地图**：研究范式、方法构件、技术路线、验证证据、成熟度、局限与发展趋势。
- **核心文献库**：题录、稳定 ID、DOI/官方来源、首次正式发表日期、版本关系、方法编码、全文状态和纳入理由。
- **核心全文阅读卡**：记录研究问题、理论、模型构件、实验设计、验证、结果、限制及对 Agent-EX 的具体启发。
- **学术发表地图**：方法研究主要发表的学科、期刊与会议，区分持续发表的研究共同体与偶发先例。
- **双轨投稿策略**：
  - 当前 Agent-EX 应用/实证论文：以社会模拟方法为基础，研究 LLM 智能体群体中的意见演化与社会互动过程。
  - 后续独立方法论文：研究 LLM-driven ABM 如何成为可控、可验证、可复现的社会科学研究方法。
- **缺口清单与研究路线图**：指出仍需全文、数据库导出、验证研究或新实验的事项。

## 证据与时间纪律

- 时间下限固定为 2022-01-01；按出版社首次正式在线发表日期判定，保留卷期年份。2022 年以前文献不纳入本轮独立检索、核心统计或阅读卡。
- 正式期刊论文、正式会议论文、预印本分别标记；预印本不能冒充正式发表。
- 每条文献保留来源、版本、检索记录、筛选理由和阅读状态。摘要不能替代全文；未核实写 pending，不猜测。
- 区分作者主张、实证结果与本项目推论。
- 不以使用 LLM、Agent 数量、事件规模、平台复杂度或日志丰富度单独认定方法创新。
- 期刊索引、scope、投稿要求、费用均使用官方来源核实，注明日期；不估造接受率、审稿周期和成功概率。
- 第一轮 57 条记录、15 张阅读卡、原始 ID、检索日志和交付物全部保留；新增分类通过扩展字段完成，不破坏历史记录。
- 不把尚未取得的 WoS/CNKI 全量检索说成已完成；明确报告公开补查与数据库规定检索的区别。

## 持续推进协议

每次 Codex 会话开始时：

1. 读取本文件、`README.md`、`progress.md`、`METHODS_FIRST_REORIENTATION.md`，检查当前分支、HEAD、工作区和项目指令。
2. 从 progress.md 的“下一项具体任务”恢复；不重新做已完成工作。
3. 每个工作批次至少交付一项可核查成果：新增核心文献与阅读卡、完成方法分类、解决一个全文/日期缺口、核验一组期刊发表先例、完成一个方法综合章节等。
4. 更新数据主表、相关报告、README 和 progress.md；记录本批检索截止日、来源、访问障碍、下一项任务与 commit SHA。
5. 仅提交本任务相关文件，保护其他 worktree 和未提交修改；不得强制覆盖远端历史。
6. 完成一个批次后，若仍有可访问且已批准的任务，直接继续下一批，不因阶段切换而重复请求用户批准。
7. 受限于工具、上下文或时间时，保存可恢复状态，列明已完成、进行中、阻塞、下一项具体任务。

**持续推进的准确含义**：在每次实际启动的 Codex 工作会话中自动恢复并继续推进，直到本会话的可执行额度或资源边界；会话结束后不得声称仍在后台自主工作。用户再次启动 Codex 时，必须从本文件和 progress.md 接续。若用户要求长期周期性提醒或外部自动执行，应另行使用用户明确授权的自动化机制，不得自行创建计划或声称已启用。
